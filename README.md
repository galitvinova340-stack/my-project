# Мониторинг кадровых назначений — Костанайская область

Реализация по [prd.md](prd.md): 3 раза в сутки (08:00/13:00/17:00, Asia/Qyzylorda)
система проверяет официальные и медиа-источники, извлекает факты о новых
кадровых назначениях, формирует карточку-досье, дописывает её в общий
Excel-файл на сетевом диске и отправляет email-уведомление.

## Структура

```
src/monitor/
  config.py            пути, расписание, список источников, секреты из .env
  models.py            модель карточки (раздел 5 PRD) + ключ дедупликации
  sources/
    akimat_site.py      сайт акимата Костанайской области
    telegram_source.py  Telegram-каналы через Telethon (личный аккаунт)
  extraction.py         LLM: сырые тексты -> факты о назначениях
  dossier.py            LLM + веб-поиск: факт -> полная карточка-досье
  state.py              локальная дедупликация + очередь отложенной записи
  excel_store.py        запись в общий Excel-файл (с проверкой доступности диска)
  emailer.py            email-уведомления
  run.py                оркестрация одного прогона (точка входа)
scripts/
  telegram_login.py            одноразовая авторизация Telegram
  register_task_scheduler.ps1  регистрация 3 ежедневных задач в Task Scheduler
tests/                  pytest (дедупликация, работа с Excel)
```

## Установка

```bash
"C:\Users\Galina\AppData\Local\Programs\Python\Python312\python.exe" -m venv .venv
.venv\Scripts\pip install -r requirements.txt
copy .env.example .env
```

Заполните `.env` (никогда не коммитится в git):

| Переменная | Где взять |
|---|---|
| `ANTHROPIC_API_KEY` | console.anthropic.com |
| `TELEGRAM_API_ID` / `TELEGRAM_API_HASH` | https://my.telegram.org -> API development tools |
| `SMTP_USER` / `SMTP_PASSWORD` / `EMAIL_FROM` | почтовый ящик, с которого будут уходить уведомления (пароль приложения, если включена 2FA) |
| `EXCEL_DIR` | путь к общей папке, по умолчанию `C:\CKB\назначения` |

Один раз авторизуйте Telegram-клиента (введёте номер телефона и код из SMS):

```bash

```

Проверка вручную (из корня проекта):

```bash

```

Регистрация расписания (08:00/13:00/17:00 ежедневно):

Тесты:

## Как это закрывает риски из раздела 7 PRD

- **Недоступность сетевого диска (7.1).** `excel_store.is_reachable` проверяет
  корень диска/сетевого пути. Если он недоступен — карточка не теряется, а
  кладётся в локальную очередь (`state.py`, SQLite) и дозаписывается
  следующим прогоном (`run.flush_pending`), без дублирования: дедупликация
  считается свершившейся сразу, независимо от того, попала ли карточка в Excel.
- **Ограниченный охват Telegram (7.2).** Используется Telethon (клиент личного
  аккаунта), а не Bot API — так можно читать историю произвольных публичных
  каналов из раздела 4 PRD.
- **Достоверность данных (7.3).** Каждая карточка получает
  `Статус проверки`: "Подтверждено официальным источником" только если сам
  факт назначения пришёл с официального источника (сайт акимата, Aqorda,
  UKIMET); иначе — "Требует проверки".
- **Устаревание источников (7.4).** Список источников — в `config.py`,
  правится в одном месте по мере появления новых каналов.

## Известные ограничения / что проверить на реальных данных

- `sources/akimat_site.py` использует универсальный разбор ссылок на странице
  новостей (я не имел доступа к живой разметке kostanay.gov.kz из этой сессии) —
  после первого реального прогона стоит свериться с логами (`logs/monitor.log`)
  и при необходимости уточнить CSS-селекторы под фактическую вёрстку сайта.
- Модель LLM берётся из `ANTHROPIC_MODEL` (по умолчанию `claude-sonnet-5`);
  если API вернёт ошибку "model not found", уточните актуальный slug модели
  в документации Anthropic и поправьте `.env`.
- `token.txt` в корне проекта содержит GitHub-токен — это чувствительный
  секрет в открытом виде; он добавлен в `.gitignore`, но стоит вынести его
  из проектной папки или переиздать, если он уже где-то засветился.
